# 第一部分：產品總覽

## 1.1 產品定位

TRIROX 是為混合型運動員（Hybrid Athletes）設計的智慧訓練 App，服務對象涵蓋馬拉松跑者、HYROX 選手、鐵人三項玩家。

## 1.2 四大訓練模組

Run（跑步）、Bike（騎車）、Swim（游泳）、HYROX Functional Strength（功能性重訓）

## 1.3 核心技術護城河

**三維動態干擾矩陣演算法**：同時評估中央神經疲勞（CNS Load，基於HRV）與局部肌肉疲勞（離心收縮負荷），解決「重訓與有氧交叉訓練」的干擾效應（Interference Effect），實現每日課表自動降階與微調（Autoregulation）。這是全產品唯一無法被競品快速複製的部分，所有頁面設計都要服務於「讓使用者感知到這個演算法在幫他」。

## 1.4 賽事模組特色

- HYROX：全17分段（8趟跑+8關卡+ROXZONE）極簡高對比 HUD 盲操計時
- Triathlon：T1/T2 轉換區計時、動態補給提示（碳水化合物/水/電解質）

# 第三部分：核心演算法規則

> 以下公式為工程可執行的**起始版本**，需要用真實用戶數據回測校準參數，但邏輯架構應照此實作，避免日後大改資料結構。

## 3.1 CNS 疲勞分數（中央神經疲勞）

**資料來源：** 晨間 HRV（建議用 rMSSD 指標，穿戴裝置或胸帶量測）

**計算邏輯：**
1. 建立個人 HRV 基線：取近 30 天 HRV 的滾動平均與標準差（需至少7天數據才能啟用，否則使用保守預設值）
2. 每日 CNS 負荷指數 = (基線平均 − 今日HRV) / 基線標準差 → 得到一個 Z-score
3. 分級：
   - Z-score < 0.5：CNS 低負荷（綠燈）
   - 0.5 ≤ Z-score < 1.5：CNS 中負荷（黃燈）
   - Z-score ≥ 1.5：CNS 高負荷（紅燈，建議降階）

## 3.2 局部肌肉疲勞分數（離心收縮負荷）

**資料來源限制：** 目前無法透過一般穿戴裝置直接量測離心收縮負荷，需採用**代理指標（proxy）計算**，公式如下：

```
單次訓練離心負荷分數 = 訓練量（時長或距離） × 強度係數 × 離心動作權重 × 使用者主觀RPE校正
```

- **離心動作權重**：需為每種訓練動作預先定義權重表（例如：下坡跑>平地跑，深蹲/蹲跳等HYROX站點的離心動作權重高於划船機等非離心動作）
- **RPE校正**：來自 03 訓練完成回報 或 01a 快速紀錄的主觀疲勞/痠痛標記，作為客觀公式的校正係數（例如若使用者標記「大腿痠痛」，該部位權重額外加成）
- 各肌群（上肢/下肢/核心）分開累加，近7天滾動加總得到「當前肌群負荷分數」

**重要工程備註：** 此為 proxy 估算，非直接生理量測，準確度上限取決於動作權重表的校準品質。若未來要接入 EMG 或更精確的動作辨識（如透過手機鏡頭或穿戴裝置的動作辨識），此模組需重構為直接量測版本。

## 3.3 訓練負荷與 ACWR（急性:慢性負荷比）

**單次訓練負荷（TRIMP-like 公式）：**
```
單次訓練負荷 = 訓練時長（分鐘） × 強度區間係數
```
強度區間係數依心率區間（Z1-Z5）或功率區間（Bike）分級給予加權係數（Z1最低、Z5最高），業界常見做法可參考 Banister TRIMP 模型。

**ACWR 計算：**
```
急性負荷 = 近7天訓練負荷加總（或滾動平均）
慢性負荷 = 近28天訓練負荷加總（或滾動平均）
ACWR = 急性負荷 / 慢性負荷
```

**風險分級（業界常見閾值，需依實際用戶回測調整）：**
- ACWR < 0.8：負荷不足（訓練量可能過低）
- 0.8 ≤ ACWR ≤ 1.3：安全區間
- ACWR > 1.3：受傷風險上升，介面需顯示警示

## 3.4 恢復分數（綜合分數，顯示於 01 首頁）

```
恢復分數（0-100） = 加權平均（CNS負荷反向分數, 睡眠品質分數, 主觀疲勞反向分數, ACWR風險反向分數）
```
各項權重需由產品/運動科學顧問共同定案，建議初始權重：CNS 40%、睡眠 25%、主觀疲勞 20%、ACWR 15%（需回測調整）。

分級對應 01 首頁的三色狀態：
- 80-100：準備良好（綠）
- 60-79：注意（黃）
- <60：需降階（紅）

## 3.5 三維動態干擾矩陣：衝突分數與 Autoregulation 觸發規則

這是核心差異化演算法的整合層，決定 04 AI調整建議是否觸發。

**衝突分數計算：**
```
衝突分數 = f(CNS負荷分數, 相關肌群負荷分數, 今日課表所需負荷類型)
```

具體邏輯：
1. 讀取今日課表類型（例如「跑步」），找出該類型主要依賴的肌群（跑步→下肢）
2. 比對該肌群目前的局部疲勞分數（3.2節結果）
3. 若 CNS負荷為紅燈 **或** 相關肌群負荷分數超過個人化閾值（如近7天累積負荷超過該肌群歷史平均的1.3倍），則判定為「衝突」
4. 衝突嚴重度分級（輕微/中度/嚴重）決定 04 頁的建議調整幅度：
   - 輕微：建議降階 10-15%（強度或時長微調）
   - 中度：建議降階 20-30%，或更換為低衝擊訓練類型
   - 嚴重：建議完全替換為恢復性訓練或休息

**觸發規則：**
- 僅在「中度」以上才主動跳出 04（避免使用者對建議產生疲乏，「輕微」等級僅在 03 提交後顯示為次要提示，不強制跳轉）
- 使用者選擇「套用建議」或「維持原課表」皆需記錄，作為未來校準建議準確度的訓練資料（不對使用者顯示此追蹤資料）

**核心產品原則（必須在介面文案與工程邏輯中都遵守）：AI 只能建議，絕不自動修改使用者課表。** 套用建議的動作必須經過使用者主動確認。

## 3.6 資料排除規則（Exclusion Flag）

當使用者在 01a 快速紀錄標記「生理狀況備註」（如感冒、生理期、出差、壓力大）時：

- 該日數據需標記 `exclusion_flag = true`
- 此標記**不影響**恢復分數計算（仍照實反映當下狀態）
- 此標記**會影響** 15訓練衝突分析（併入11分析頁的相關性洞察區塊）的歸因邏輯：帶有 exclusion_flag 的日期，不得被拿來作為「訓練導致表現下降」的因果證據來源，避免污染衝突歸因模型的訓練資料

## 3.7 傷病與限制的優先權規則

當「運動能力設定」（3.8節）與「傷病與限制」設定衝突時（例如使用者自評能力為進階，但傷病欄位標記膝蓋舊傷）：

- **傷病與限制永遠優先**，作為硬性排除規則（絕對排除特定動作或降低特定部位負荷上限）
- 運動能力設定僅在傷病限制範圍**內**決定訓練強度，不能覆蓋傷病的硬性限制

## 3.8 課表生成邏輯（初始課表）

初始課表生成依賴「訓練設定」中的三組輸入參數：
1. 可訓練時間（天數、時段、休息日、器材場地）→ 決定課表能安排在哪些時段、哪些訓練類型
2. 運動能力設定（跑步能力、Bike FTP、游泳配速、HYROX能力、重訓程度）→ 決定初始強度基準
3. AI訓練偏好（保守程度、優先保護的訓練類型、連續訓練日容忍度、單次最長時間）→ 決定課表生成時的排課策略偏好

初始課表生成後，隨著 03 訓練完成回報累積實際數據，運動能力基準值需定期（建議每2-4週或累積一定訓練次數後）重新校準，不是一次性設定。

# 第四部分：各頁面完整規格

## 4.1 今日 Today 分頁

### 01｜今日首頁

**目的：** 10秒內回答「我今天狀態如何、該練什麼」

| 區塊 | 內容 | 資料來源 |
|---|---|---|
| 恢復狀態卡 | 恢復分數（0-100，三色分級）、HRV較昨日變化、CNS疲勞等級 | 3.4節公式輸出 |
| AI建議提示 | 條件觸發，顯示衝突原因摘要+「查看建議」按鈕 | 3.5節衝突分數達中度以上時顯示 |
| 今日課表卡 | 項目圖示、預計時長/距離、目標強度區間 | 當日課表資料 |
| 賽事倒數 | 優先賽事名稱+剩餘天數 | 08賽事中心資料 |
| 快速紀錄入口 | 見01a | — |

**互動邏輯：** 若無衝突，AI建議卡不顯示；若前一則訓練尚未回報（03），顯示提醒Badge。

### 01a｜快速紀錄（彈出式子功能，非獨立頁面）

**目的：** 補足未觸發03時段的主觀生理狀態，避免演算法誤判。

**觸發方式：** 首頁快速紀錄卡片點擊 → 底部彈出表單（bottom sheet）

**表單欄位：**
| 欄位 | 型態 | 用途 |
|---|---|---|
| 睡眠時長/品質 | 滑桿或星級，選填 | 裝置未同步時的備援輸入，餵給3.4節恢復分數 |
| 主觀疲勞感 | 1-5級距，選填 | 校正HRV客觀數據與主觀感受落差 |
| 體重 | 數字輸入，選填 | 長期趨勢，不進恢復分數計算 |
| 肌肉痠痛標記 | 簡化人體圖，二元判斷+部位 | 餵給3.2節離心負荷proxy計算的RPE校正項 |
| 生理狀況備註 | 預設標籤+自由文字，選填 | 觸發3.6節exclusion_flag |

**關鍵規則：** 全欄位選填；生理狀況備註觸發的 exclusion_flag 需正確寫入當日資料列。

### 02｜今日課表詳情

**目的：** 明確告知今天要練什麼

**內容：**
- 項目類型+圖示
- 結構化課表：熱身→主課表（配速/功率/心率區間）→收操
- HYROX訓練日：顯示鎖定關卡動作與組數/負荷
- 簡短說明文字（為什麼排這個強度，取自3.5節衝突判斷邏輯或課表模板）
- 「開始訓練」「回報訓練」按鈕（後者進入03）

**資料需求：** 結構化課表資料表、當日課表是否已被04調整的版本標記

### 03｜訓練完成回報

**目的：** 收集訓練結果，餵給3.2/3.3節計算模型

**內容：**
- 裝置自動帶入：實際時長/距離、平均心率、配速/功率
- 使用者填寫：RPE（1-10）、整體疲勞感、痠痛部位（人體圖點選）
- 備註欄（選填）
- 送出後：無異常→顯示確認畫面返回01；偵測衝突→導向04

**資料需求：** 裝置同步API、人體部位標籤結構

### 04｜AI調整建議（條件觸發頁）

**目的：** 解釋調整原因，使用者自主決定是否套用

**內容：**
- 觸發原因說明（取自3.5節衝突分數計算結果）
- 視覺化證據：HRV趨勢小圖+肌群負荷分數
- 建議方案 vs 原訂課表並排比較
- 「套用建議」／「維持原課表」按鈕

**核心規則：** AI只能建議，不自動修改課表（見3.5節）。使用者選擇需被記錄供後續校準（不對使用者顯示）。

## 4.2 計畫 Plan 分頁

### 05｜計畫總覽

**內容：**
- 訓練週期階段條（基礎期/建構期/巔峰期/減量期），標示目前所在階段與距下階段週數
- 本週課表摘要卡（各項目次數、完成率），點擊進入06
- 多賽事並行進度條（並排或堆疊顯示，主要賽事用強調色區隔）
- 整體完成率（圓環圖：本週已完成/計畫課表數）

**待確認邏輯：** 07課表編輯調整後，05的完成率與週期階段判斷是否即時重算——建議採**動態追蹤**（每次編輯觸發重算），而非固定排程快照，理由是使用者常態調整課表時，若階段劃分不跟著變動，會造成「明明常常調整卻始終顯示同一階段」的失真體驗。

### 06｜週課表

**內容：**
- 週視圖（7天×項目類別網格或時間軸卡片）
- 每張課表卡顯示項目、時長/強度、完成狀態
- 點擊進入02（未來日期為預覽模式，不可回報）
- 編輯入口進入07

### 07｜課表編輯

**內容：**
- 拖拉式或表單式日期調整
- 項目替換選單
- 強度/距離滑桿調整，**即時呼叫3.5節干擾矩陣模型做衝突預檢**，顯示是否會與其他項目產生衝突
- 儲存前顯示變更摘要

**設計考量：** 與06分頁而非合併，避免手滑誤觸；三項目複雜排程需要獨立編輯空間。

### 08｜賽事中心

**重要工程備註：此頁面為單一共用畫面，有兩個進入入口，不需要開發兩套功能：**
- 從「計畫」05計畫總覽進入：情境是查看備賽進度，上下文銜接05/06/07的訓練週期資訊
- 從「我的」16我的首頁的「我的賽事」入口進入：情境是純管理型操作（新增/修改/排序賽事）

兩個入口導向同一組畫面（08/09/10），畫面內容本身不因入口不同而改變呈現方式，除非未來使用者測試證實有動線問題，才需評估是否為不同入口客製化呈現重點。

**內容：**
- 賽事卡片列表：類型圖示、名稱、日期、優先程度標籤
- 「新增賽事」按鈕→10
- 點擊卡片→09

### 09｜賽事詳情

**內容：**
- 賽事基本資訊：日期、地點（選填）、目標成績
- 剩餘備賽天數+對應訓練週期階段
- 備賽進度條（課表完成率+體能測試結果綜合計算）
- 優先程度調整（影響05與04的排課邏輯權重）
- 編輯／刪除

### 10｜新增賽事

**內容：**
- 選擇賽事類型（Marathon/HYROX/Triathlon，含子分類）
- 輸入日期、目標成績
- 設定優先程度
- 若已有其他賽事，提示是否共用訓練週期

## 4.3 分析 Analysis 分頁（單頁版，最終定案）

### 11｜分析總覽（唯一頁面，單頁捲動，無分頁籤）

**設計原則：** 只回答「身體能不能承受訓練」與「有沒有變強」兩個問題，越上方優先權越高。原規劃的12/13/14/15獨立頁面內容已合併於此。

**區塊1：恢復分數（含AI建議）**
- 大圓環分數（0-100，三色分級，公式見3.4節）
- 三欄小卡：HRV（數值+較昨日變化+近7天趨勢）、睡眠（時數+變化+趨勢）、主觀疲勞（分數+變化+趨勢）
- AI建議直接嵌入本區塊底部（一句話說明今天該注意什麼）

**區塊2：訓練負荷（ACWR）**
- 數值+風險等級（公式見3.3節）
- 近7天負荷長條圖

**區塊3：相關性洞察**
- 只呈現一則最新、最重要的因果解釋（取自3.5節衝突分析結果，排除帶有exclusion_flag的資料，見3.6節）
- 格式：兩變因交集說明+簡短建議文字
- 全頁視覺焦點，此為核心差異化功能的唯一呈現位置

**區塊4：表現趨勢（四宮格）**
- 跑步配速／單車FTP／游泳配速／HYROX總時間，各自現值+變化%+迷你趨勢線
- 不分頁籤，四項同時呈現

**區塊5：比賽預測**
- 只顯示最近一場主要賽事：預估完賽時間+達標信心度（百分比+進度條）

**明確排除（不放入此頁）：**
- 肌群負荷人體熱區圖（資料精準度未定案前不做精緻視覺化）
- 個人最佳成績（PB）追蹤（改放「我的」分頁的已完成賽事紀錄）

# 第五部分：核心資料模型（Entity 概覽）

供工程師建立資料庫schema參考，非最終欄位定義：

- **User**：基本資料、運動能力基準值（含歷史版本供追蹤校準）、訓練偏好設定、AI偏好設定
- **Race**：類型、日期、目標成績、優先權重、狀態（備戰中/已完成）
- **WorkoutPlan**：日期、項目類型、結構化課表內容、版本標記（原始版/AI調整版）
- **WorkoutLog**：對應WorkoutPlan、實際數據（裝置同步）、RPE、痠痛標記、時間戳
- **DailyCheckIn**（快速紀錄）：日期、睡眠、主觀疲勞、體重、痠痛標記、生理狀況標籤、exclusion_flag
- **RecoveryMetric**：每日HRV、恢復分數、CNS負荷等級（衍生計算結果，可考慮做成快取表）
- **MuscleLoadScore**：各肌群、日期、離心負荷分數（衍生計算結果）
- **ConflictEvent**：日期、衝突類型、嚴重度、涉及的課表與生理數據關聯、使用者是否採納建議
- **InjuryRecord**：部位、狀態、限制動作、建立/更新時間
- **DeviceConnection**：裝置類型、授權範圍、最後同步時間
